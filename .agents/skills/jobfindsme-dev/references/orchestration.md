# 自动开发调度

用户于 2026-09-18 授权当前会话调度、新会话分阶段实施，使用 Sol 中等推理，不设置 human review。

## 调度者

1. 读取项目任务、交接、`docs/desktop/ORCHESTRATION.md` 和 Git 状态。先确认已有实施会话是否仍运行，避免重复派工。
2. 用 list_projects 选择项目，create_thread 创建阶段任务，模型 `gpt-5.6-sol`、thinking `medium`。任务正文必须明确实际代码目录、任务 ID、UI 基线、最小验收、禁止发布及真实投递。
3. 同一实际代码目录只允许一个写入会话。调度者在实施期间只读；需要调整计划时先等待实施者停止，再修改。审查会话只读代码，只写独立报告。
4. 使用 wait_threads 获取完成或需要处理的事件；等待不超过 60 秒，避免反复读取无变化输出。实现完成后核对改动和证据，不重复已通过的同版本检查。
5. 有有效缺陷时发回原阶段修复；完成后启动下一阶段。会话中断时优先恢复原任务，不能把中断当完成。鉴权、隐私、迁移等重要边界必要时创建独立 AI review。
6. 外部登录、依赖下载或权限阻塞必须具体记录；继续无依赖任务。允许拆分离线实现与真实验证，保留最终真实验收，禁止降低完成标准。
7. 用户停止则停止派工。无人值守跨轮推进只在实际建立当前会话 heartbeat 后承诺；定时调度检查已有会话，不并发重复启动。最终全部完成或只剩用户依赖时停止调度并报告。

## 实施者

完成或遇到必须由调度者处理的阻塞后，先保存 tasks/evidence/HANDOFF，停止业务写入，再通过 `send_message_to_thread` 主动回传调度任务 `01a0b37c-a94a-76a0-a521-5fdfc6f3977c`（host local）。消息包括本会话 ID、完成任务、验证、证据路径、阻塞和建议下一步，并明确“已停止写入，可接管”。这是用户明确要求的项目内部完成通知；不发送到其他人或外部渠道。回传失败如实记录，由 heartbeat 兜底，不无限重试。调度者收到通知后先核对 wait_threads，避免交接竞态；活跃调度用完成事件等待，10 分钟 heartbeat 只作兜底。

读取本 skill 与项目文档，按调度指令连续完成本阶段，不创建下一阶段会话。保留已有变更，更新 tasks.json、对应 evidence 和 HANDOFF。结束报告完成项、最小验证、阻塞与下一步；完成不了的验收不得标 done。

阶段建议：基础（D01/D02）→简历与模型（D03/D08）→搜索与投递（D04/D05/D06）→简历编辑与研究（D07/D09/D10）→调度与集成（D11/D12）。以 tasks.json 依赖为准，外部阻塞时选择其他就绪任务。

2026-09-21 起允许建立本地 Git 基线，之后每个独立修复验证通过后提交一次；禁止自动推送和发布。不执行真实投递，不使用用户密钥做未经授权的付费验证。已有 UI 是视觉基线，最终生产 UI 必须接通真实状态，演示数据不得冒充真实来源。
