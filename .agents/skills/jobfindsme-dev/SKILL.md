## 按用户意图执行

- **全自动开发 / 阶段会话调度**：用户已授权当前会话担任调度者，按 [references/orchestration.md](references/orchestration.md) 连续启动、等待、验收和衔接阶段；阶段实现使用 `gpt-5.6-sol`、`medium`。此模式覆盖下方普通“继续开发”一次一个任务的默认限制。

- **查看进度 / 审核方案**：只读并报告，不启动开发、不改任务状态。
- **继续开发 / 实现任务**：恢复当前未完成任务；没有当前任务时，选依赖已完成的首个 pending 任务。实现、验证、更新记录，不在每步结束后询问是否继续。
- **持续开发 / 完成阶段**：在授权范围内连续推进可执行任务，直到指定目标完成或没有可做的独立工作；不自行承诺后台持续运行。
- **更新计划**：将用户新决定写入权威方案和受影响任务，保留 ID 与已完成证据；不要只在对话里记住。
- **验收 / AI review**：仅在用户要求或本轮风险确有必要时执行；独立 review 流程见 [references/ai-review.md](references/ai-review.md)。

本 skill 的创建/安装不等于授权当场实现整个项目。正常“继续开发”默认完成一个可验收任务；较大任务拆成可独立验证的小任务，更新依赖后继续。不要用阶段性计划代替已获授权的实施。

## 执行与恢复

1. 先复核 `current_task`、in_progress 任务及交接；若代码已经完成，只补必要验证，不重复实现。
2. 依赖未满足不抢跑。blocked 任务先看阻塞是否消失；平台登录等需要用户动作时记录明确缺口，可继续不依赖该项的工作。
3. 选定任务后更新 `status=in_progress` 与 `current_task`。写清本轮改动范围和最小验收，避免顺手大规模重命名或拆分目录。
4. 尽量复用现有连接器、解析、SQLite 和质量样例。只按需新增依赖；实现桌面端功能时同时接通用例和错误状态，不能用硬编码结果冒充可用功能。
5. 完成验收并记录证据后才标 done；清除 `current_task`。部分完成保持 in_progress，受外部条件阻塞则标 blocked，填写 `blocker`。
6. 更新 `docs/desktop/HANDOFF.md`：当前状态、变更、最小验证、遗留问题、下一步。简短覆盖更新，不累积工具调用流水账。

`tasks.json` 是唯一任务状态源。不要维护第二份重复进度表；新增子任务沿用其字段约定。
每项验收都有对应证据：命令或操作步骤、实际结果、差异标识、限制。证据放 `docs/desktop/evidence/<task-id>.md`，引用到任务 `evidence` 列表。
没有真实接入条件时可以完成独立的离线组件，但不能把整个平台接入任务标 done；改用拆分任务表达进展。

## 必须保留的产品决定

- 最终桌面产品不保留 MCP；先跑通替代链路，再按 D12 清理旧分发，开发管理 skill 保留。
- BOSS/智联/前程无忧未登录禁止实时检索；猎聘可尝试匿名路径。前后端都做门禁，登录成功与字段/分页可用分别验证。
- 有当前已确认简历时，简历必须同时参与检索词生成与排序；上传待解析/确认不静默退回无简历模式。隐私字段不进入检索关键词。
- 岗位分页、稳定排序、已看/收藏/已投递分开；短列表不让详情掉到末尾。原页由用户完成投递，打开链接不算已投递。
- 简历支持上传、编辑、模板与导出；Prompt 修改基于真实项目事实生成可采纳的版本补丁，原版不自动覆盖。脱敏仅影响分析副本。
- 口碑结论关联真实引用；没有证据时明确说明。定时任务本地执行，保留版本快照、补跑和失败状态。

## 验证与 review 的限度

按 `DEVELOPMENT.md` 的风险表选择最小有效验证；说明要阻止的实际失败，不以测试数量或覆盖率为目标。
复用已有测试，确定性边界使用小样例；真实来源只在接入变更或验证缺失时做一次必要实测。不要循环联网测试或实际提交申请。
文案/样式/文档只需相关检查，不写镜像实现的测试或全页面文本快照。已有检查对同一差异通过后不重复运行；新改动只复跑受影响部分。
全量回归留在阶段集成或发行关口，必要时一次执行；不把多轮 AI review 当作每个任务的固定流程。

用户已明确取消开发过程的 **human review 关卡**。普通实现、测试、缺陷修复和阶段衔接不等人工验收。
必要的独立 AI review 在新会话进行，由主开发者核实发现并修复；它不取代测试，也不自动授权发布、真实投递、账号操作或删除用户数据。
需要真实登录、验证码等用户操作时准确说明外部依赖，不把它包装成“请 review 我的代码”。
2026-09-21 用户已授权本地 Git 基线与后续独立修复提交：针对性验证通过后，每个独立修复提交一次，连同证据与交接。保留历史和用户修改，排除私密数据及构建产物；禁止自动推送或发布。后续授权变化以用户最新指令为准。
