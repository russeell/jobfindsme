# 技术方案

## 1. 单机分层

```text
React + TypeScript 界面
  → 受限 preload IPC → Electron 主进程
      ├─ WebContentsView：平台原页、独立会话、用户投递
      └─ 本地 FastAPI 子进程 → Python 用例服务 → SQLite / 文件 / 来源适配器
```

Electron 管窗口、浏览器、进程生命周期和系统通知；Python 复用现有检索核心，管理业务数据和任务。
本地 API 只监听回环地址、使用启动时令牌；远程平台页面禁用 Node 集成、启用隔离与沙箱，不暴露业务 IPC。
不要把整个 Python API 或任意脚本执行能力暴露给网页。

平台会话由 Electron 管理，各平台使用独立持久分区。浏览器适配器通过受限动作完成来源指定的查询/读取，结果回交 Python；不导出 Cookie，不开放任意 URL/任意脚本桥。
人工浏览与后台检索使用分开的视图、复用同平台会话，避免检索跳转打断投递。
猎聘沿用可用的匿名 HTTP 路径；其余三平台同时检查登录状态与对应检索能力。

来源实现分为两个可离线验收的前置边界：D04a 在 Electron 中创建隔离 `WebContentsView`（D23 起仅后台执行器保留来源白名单），每个平台以 `persist:jobfindsme-source-<id>` 隔离持久会话，并为人工可见视图和后台检索视图分别创建 webContents；远程页不配置 preload、禁用 Node、启用 context isolation 与 sandbox。D04b 在 Python 中维护来源执行契约，后端先检查登录与能力状态，再调用现有连接器；连接器不能自行把“返回空列表”升级为来源可用。

来源状态分别保存 `session / list / detail / fields / pagination`，并附最近验证时间和限制。BOSS、智联、前程无忧只有 session 已验证且列表能力已验证才可实时执行；猎聘可按匿名列表能力尝试。公司官网逐站记录校招/社招入口及同样的能力维度，默认 `unverified` 和禁用，不能以招聘首页可打开代替岗位能力。

## 2. 检索、排序、分页

1. 将当前简历的已确认技能、项目、经历与用户意向生成有限组检索词；只传必要词语给招聘平台，不传完整简历。
2. 通过登录/能力门禁后并发检索不同来源；按来源限流，分页有时间/页数预算，去重后增量展示。预算达到不等于全网搜完，显示覆盖与可继续获取状态。
3. 统一字段、保留来源证据和时间；城市等硬条件采用通过/不通过/未知三态。新交互检索固定保留未知，未知不表示满足；历史任务按冻结策略执行。
4. 薪资统一可比较月薪；新交互检索固定区间交集，移除严格包含选项；旧任务保留冻结值。年薪、日薪和奖金不做无依据换算；下限不得大于上限。
5. 对有充分 JD 的岗位按模板评分，固定规则版本，分数与覆盖度分开。默认试验权重为职责 35、技能 30、项目 25、加分项 10，总和 100；通过标注样本检验后调整。
6. 保存 `search_run + result_revision + ordered_job_ids`；页面按快照排名切片，稳定以 job_id 打破同分。后台新结果提示刷新，不能导致翻页重复或漏项。

每次运行绑定 `resume_version_id / rule_version_id / filter_snapshot`。简历修改后新搜索使用新版本，旧结果可追溯；定时任务默认绑定创建时版本，更新版本需显式操作。
字段读取与硬过滤采用确定性代码；模型不可绕过登录门禁、硬条件或伪造缺失字段。

## 3. 简历与模型

- `原文件 → 文本提取 → 结构化事实 → 用户核对 → 当前简历版本`。复用现有解析器；扫描件 OCR、DOC 转换作为独立可选本地能力，有体积/页数/超时上限和明确失败提示。
- 内容采用统一结构（基本信息、教育、经历、项目、技能）；模板只负责排版。编辑内容生成版本，保留父版本和修改来源。
- Prompt 修改输入为用户指令、选定段落、项目事实、可选 JD；输出为结构化补丁及依据。展示逐段差异，支持采纳/拒绝/继续修改；应用补丁前检查基础版本，防止覆盖并发编辑。
- 身份信息过滤在任何模型调用前统一执行；用户可选择不过滤并预览发送内容。简历正文、API Key、登录信息不写入日志和管理 skill 的交接文档。
- PDF 使用独立简历预览页打印导出；DOCX 用同一内容结构映射文档模板；MD 直接导出。导入任意旧简历后不承诺原版式无损还原。
- 模型提供统一 `generate_structured / stream / cancel / usage` 契约，分别适配 OpenAI 兼容、Anthropic、Gemini；服务商/模型列表配置化。首个适配器完成后逐项验证扩展，不假定所有接口通用。
- API Key 使用系统凭据存储并经受限进程间通道提供；日志脱敏。模型不可用时保留检索、人工编辑与导出，明确暂停 AI 修改/研究。

## 4. 研究与调度

研究仅保留公开来源口碑调查与针对 JD 修改简历；保存 `Evidence(url, platform, published_at, retrieved_at, company, team, excerpt, limitations)`。
评价需校验公司/部门/职级/时间相关性；不足时返回证据不足。引用 ID 对应真实原链接，不编造评价和 URL。社区登录受限时明确提示，可接受用户提供链接或摘录并注明来源。

本地持久调度服务与桌面生命周期协作：关闭窗口留后台与完全退出分别处理。SQLite 保存任务及执行记录；`task_id + scheduled_at` 唯一键避免重复执行，多次错过合并为最多一次补跑。
处理时区、单任务重入、登录失效、部分来源失败和通知去重；关机/休眠不能承诺执行，不做自动唤醒。只对新增、重要变化或需要用户处理的失败通知。

## 5. 数据与接口边界

在现有表上增量迁移，先备份验证，不另建一套互不兼容数据库。新增领域实体：

| 领域 | 新增实体 |
| --- | --- |
| 检索 | search_runs、search_result_items、scoring_rule_versions |
| 简历 | resume_versions、resume_sections、resume_edit_sessions、resume_patches |
| 记录 | job_read_events；收藏和投递复用并修正现有状态模型 |
| 研究 | research_reports、research_evidence |
| 调度 | 审查旧 monitor 表后迁移/复用 tasks、task_runs，避免双份调度状态 |

建议本地 API：`POST /search-runs`、`GET /search-runs/{id}/jobs?page=`、`GET /jobs/{id}`、`POST /jobs/{id}/events`；`/resumes`、`/resume-versions`、`/edit-sessions`、`/research-runs`、`/sources`、`/tasks`、`/model-connections` 按用例扩展。
长任务返回任务 ID，由统一事件流报告进度、取消和失败；不让界面长时间阻塞。

## D21–D23 用户追加决定（2026-09-19，覆盖早期同类约束）

- 发现/记录复用岗位操作组件：投递链接为主操作，收藏是可切换星标，已读/已投递在次级状态菜单更新。打开链接不等于投递。横向筛选弹出浮层，不推移结果；支持键盘退出、焦点返回和原生网页遮挡。

- 本地模式不调用模型，自由提示词明确不生效。显式保存模型模式后，先显示本地结果，再对前1–20个候选执行一次有界重排（60秒、最多8000输出tokens）；其余候选顺序保留。模型提供双向逐字证据，未知可不给分；集合/分数/引用验证失败保留本地结果。派生新快照，不覆盖原始或历史结果。界面显示覆盖与取消，定时部分失败同样可见。
- 模型连接配置随规则冻结；主进程从安全存储取密钥，仅通过鉴权回环API发送，不存入规则/renderer。简历分析排除基本信息并过滤常见身份字段，JD作为不可信资料。匹配规则页不再保留实际岗位试算区；保留规则编辑、保存启用与四维设置。无确认简历展示“尚未评分”。实际付费模型效果另行验证。
- 前台浏览允许普通HTTP/HTTPS网页、ATS/SSO跳转及跨域新标签，不按招聘域名名单拒绝。登记平台入口仍用固定分区，新窗口继承打开者分区；未知入口用独立通用持久分区。前台放开不赋予自动采集或后台提取资格，来源能力/登录门禁仍有效。
- 保留sandbox、contextIsolation、webSecurity、证书检查，远程无Node/preload/应用IPC。特殊协议、账号内嵌URL与本地/内部地址受限；站点权限需明确选择，下载走保存对话框，不自动唤起外部应用。本产品使用Chromium网页行为，不承诺Chrome全部扩展或系统整合能力。
