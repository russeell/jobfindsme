# D04b 简历检索词与有预算来源执行契约验收证据

日期：2026-09-18。结论：离线前置和猎聘既有真实连接器接通完成；未验证来源未宣称接入。

## 实现

- 新检索前置服务在任何连接器执行前检查 active resume draft；上传待核对时返回冲突，不静默退回无简历模式。有当前确认版本时响应绑定 `resume_version_id`，首个实际查询组合用户意向与确认技能；基本信息段从不读取，常见身份字段再次过滤，只生成有限关键词而不发送完整简历。
- renderer 只提交 `live_search_enabled` 来源，Python 后端再次逐来源执行 session/list 能力门禁；直接伪造 BOSS/智联/前程无忧 source ID 也不会调用适配器。
- `BudgetedSourceExecutor` 以页数和时间双预算执行 paged adapter，明确返回 `pages_fetched / coverage_status / can_continue / next_cursor / stop_reason`。达到预算报告 partial，不声称全网完成。
- 猎聘复用现有 `LiepinPureHttpConnector`，通过单页兼容适配器进入新契约；D01 已有的 42 条匿名列表实测路径没有改变，因此本轮不重复联网探测。三个登录平台明确要求 Electron session bridge，不把旧公共 CDP 作为桌面生产前置。
- 腾讯、字节跳动、阿里巴巴、美团、百度、京东、网易、快手、小米、滴滴、拼多多均有独立能力记录；校招/社招入口、列表、详情、字段、分页尚未验证，全部保持 disabled/unverified。

## 验证

- `uv run pytest -q tests/desktop_api/test_source_search.py tests/desktop_api/test_app.py` → `17 passed`，1 个第三方 Starlette deprecation warning。覆盖待确认阻断、隐私关键词、强制绑定确认版本、三平台后端门禁、11 官网默认状态、分页预算/继续游标、猎聘连接器工厂与 API 端到端门禁。
- 受影响 Python `ruff check` 与 `ruff format --check` 通过。
- 桌面 `npm run typecheck`、`npm test`（11 passed）与 `npm run build` 通过；发现岗位页已接真实 `/v1/source-searches`，来源失败与零岗位分别展示。

- 尚未实现 D05 的稳定结果快照、硬过滤和正式分页，也未实现 D06 的岗位原页投递/记录；本轮只展示来源记录与覆盖状态，没有抢做后续任务。
