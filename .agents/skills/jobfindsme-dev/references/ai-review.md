# 独立 AI review

仅在需要独立判断时读取本文件。适用：会话/鉴权边界、敏感信息发送、数据库迁移、跨模块契约、阶段集成，或当前实现存在未解决的实质性疑点。
一般文案、样式、小型局部修复和 skill 创建不需要额外 review 会话。

## 准备具体审查包

实现和针对性验证完成后，写 `docs/desktop/evidence/<task-id>-review-request.md`：

- 项目绝对路径、任务 ID、验收要求、精确改动范围。
- 基线 commit、目标 commit；有未提交修改时必须同时包含 tracked diff、untracked 文件清单及内容摘要/哈希。仅写 HEAD 不足以定位实际改动。
- 已运行检查及结果、实际待审查问题；不要预设“应该通过”。
- 只读限制、输出报告路径和禁区：不改业务、任务状态或用户文件，不做真实登录、模型付费调用、投递、提交或发布。

审查期间不修改所审范围。可继续不相交工作；若目标发生变化，记录旧结论已过期，只补审受影响差异。

## 新会话执行

用户已明确允许必要时在新 session 做 AI review。工具可用时：

1. 使用 `list_projects` 定位正确项目。
2. 使用 `create_thread` 创建独立审查任务。对于未提交差异，明确选择该项目本地目录只读审查（local），避免新 worktree 丢失未提交内容；对已有提交可用 worktree 并提供确切 ref。
3. Prompt 提供审查包路径，要求独立阅读验收和实际代码，输出有依据的缺陷及严重性、文件/行号、触发条件、最小修复建议；没有发现就直说，并列未验证范围。
4. 指定仅可写审查报告路径，禁止开发修改；其余全部只读。模型沿用用户默认，不擅自指定另一模型或扩大权限。
5. 记录返回的 threadId，使用 `wait_threads` 获取完成结果；避免重复创建同一轮 review。会话创建需按工具规则向用户提供任务入口。

新会话工具不可用时保留审查包。不能声称已经完成独立 review：低风险可记录自审，高风险未解决疑点保留阻塞；可先完成独立且不依赖其结论的任务。

建议 Prompt：

> 对指定审查包中的 JobFindsMe 改动做独立只读 review。先读当前项目 AGENTS.md 和任务验收，再检查精确差异。关注实际行为、回归、权限与数据边界，不要求无关重构或增加无价值测试。不要接触真实账号、简历、密钥或网络服务，不修改代码或任务状态。仅将报告写到指定位置，按严重性列有证据的发现；没有发现也明确给出审查范围及限制。

## 处理结论

主开发者核实每条发现，不机械采纳。修复真实高风险/阻塞缺陷，只跑受影响验证；未采纳项写简短依据。
仅当修复改变关键边界或仍有实质疑点时，请同一审查会话复核差异；不为得到“零建议”无限循环。
验收满足且阻塞缺陷解决后自行更新任务状态，无需 human review。
