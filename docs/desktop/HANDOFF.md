## D64 研究 Agent 实施边界

沿用 Pi 的单一模型/工具循环、现有密钥存储、受限浏览器、研究服务与报告存储；项目侧掌管对象识别、工具权限、预算、证据质量、引用校验、报告版本和工作区隔离。已将 `search_public_evidence` 一次调用即保存报告的路径替换为 `find_evidence`、`search_web`、`read_page`、`read_job`、`read_browser_page` 工具适配；原文读取失败后才允许隔离浏览器回退。搜索摘要不得作为证据。普通聊天不启用网页工具，也不自动生成报告。

本地 D64 验收：研究页只有问题输入、模型选择、发送/停止，明确公司无需岗位链接，歧义问题在对话中追问。SQLite 将对话、执行与报告分别保存并按工作区隔离；执行轨迹含预算、证据和失败，取消/失败不覆盖旧报告。研究模型须返回陈述、原文连续引句、证据 ID、类别和范围；前后端共同拒绝无效证据、主体/否定/时间/地区/数字/上市状态不符及明显过度归纳。展示区标注直述或限定归纳、原文、证据 ID、来源类型和适用范围。相同原文上的实质陈述变更也生成新版本；普通追问不自动生成报告。此校验是保守的文本支持筛查，不能替代真实语义核验。Python 定向 10 项、Node 全套 94 项通过（含本地模拟模型的 Pi 多工具与普通追问链路）；此前 Python 全套 372 项及两个回环测试通过。隔离原生包取得默认、860px 窄窗、600px 矮窗、历史重开、无依据回答和追问截图，均为明确标记的合成数据。真实付费模型、真实研究质量未验证，D64 保持进行中。测试版为本地 `outputs/JobFindsMe-D64-Review.app`，未推送或发布；截图与条件见 `outputs/D64-QA.md`。

2026-09-25 正确性补修：来源后续页失败时保留已读岗位并标记部分结果；历史对话完整存储，重开恢复岗位/公司上下文，切换会话时只接收当前会话流；问题上限统一为 700 字。检索运行绑定岗位版本快照，旧运行无法确认原快照时明确标记且不展示旧分数。研究执行记录关联会话，区分原文证据与最终回答；搜索预算收紧，原文证据 ID 由读取内容生成；取消后可立即重试。补修后 Python 全套 388 项、Node 全套 103 项及合成/金标准评估门槛通过，桌面构建通过；Windows CI 增加时区依赖及 UTF-8 设置，尚未在 Windows 实机运行。原生界面与真实模型仍沿用上述验收边界。
