# 重构方案

## 1. 产品范围

建设本地桌面求职工作台：简历 → 检索与分页 → 研究 → 简历定制 → 用户投递 → 记录与定时检索。
采用简洁灰白视觉；桌面岗位列表与右侧工作区稳定并排，窄屏切换视图，详情不能掉到整个列表后面。

| 模块 | 必须实现的行为 |
| --- | --- |
| 发现岗位 | 默认每页 10 条，可选 10/20/50；不限总推荐条数；按匹配排序，支持城市、薪资范围、校招/社招、用工类型、经验、来源和已看过滤；来源跨页同步多选，用于下次检索，仅请求已选且可用来源 |
| 简历驱动 | 有已确认当前简历时，检索词生成和匹配排序必须绑定该版本；上传尚未解析/确认时先完成处理，不静默退回无简历检索；无简历可按明确意向检索 |
| 平台准入 | BOSS、智联、前程无忧未登录关闭实时检索，后端同样拦截；猎聘允许匿名尝试，受限时明确报告，不能保证永久免登录 |
| 来源管理 | 四个平台及大型公司官网；分别显示登录、列表、完整 JD、字段覆盖、分页、最近验证时间；只启用已通过验收的能力 |
| 右侧浏览器 | 平台原页面登录、详情和投递；最终投递由用户操作；打开投递页不等于已投递，记录可由用户确认及撤销 |
| 岗位研究 | 用户 2026-09-19 澄清：保留页面，仅保留口碑调查、针对 JD 修改简历两个模块，删除应聘准备；直接粘贴链接自动解析 JD，从发现或已看过带入后可确认并研究；口碑评价保留原链接、时间与适用范围，JD 可直接带入简历编辑器 |
| 简历编辑 | 上传 PDF/DOCX/MD/TXT；DOC 转换与扫描件 OCR 按任务增加；结构化编辑、模板预览、Prompt 修改、逐段采纳、历史版本与导出 |
| 隐私选择 | 用户选择保留或过滤身份字段；默认过滤分析副本，发送前可预览；原始投递文件独立保存与选择 |
| 匹配规则 | 内置模板与自定义权重；先硬过滤后评分；有分项证据和信息完整度；缺失关键 JD 暂不评分，不伪造高匹配 |
| 定时检索 | 条件及版本快照、时区、暂停、执行历史、补跑策略；新增/重要变化通知；登录失败与零新增分开记录 |
| 模型配置 | 主流服务与自定义端点、模型 ID、连接测试、任务用量；不同协议独立适配，密钥留在本地安全存储 |

“根据项目修改简历”指基于用户提供并确认的真实项目经历；代码仓库不默认扫描，成果数字不由模型补造。
Prompt 修改生成新草稿，用户可以逐段采纳、继续对话或撤销；基础简历不被自动覆盖。

## 2. 复用与替换

- 复用：`connectors/`、`core/search.py`、`importing/`、`matching.py`、`profiles/`、`tracking.py`、SQLite 迁移及相关质量样例。
- 扩展：检索会话分页、可配置评分、真实阅读事件、简历版本/编辑、评价证据、模型适配、调度服务。
- 新建：Electron + React 桌面端、本地 API、会话浏览器桥。
- 收尾移除：MCP 接口、求职 Agent skill/插件分发、相关安装器和专属测试；保留核心评测及桌面必需的诊断。
- 后续开发管理 skill 属于开发工具，与被移除的求职 Agent skill 不同。

现有 `include_seen` 更接近“展示过”；迁移时保留旧展示记录，新建阅读事件，不把历史推送批量标成用户已看。
现有 `get_jobs` 分页不直接等价于稳定的按匹配分分页，需要增加检索结果快照。
现有 PDF/DOCX/MD/TXT 解析可复用；旧 DOC、OCR、模板编辑和导出不是现有能力。

## 3. 开发阶段与退出条件

1. **接入验证与底座（D01–D02）**：验证内嵌登录/检索/跳转链路，建立桌面端与 Python 核心通信；不重写检索引擎。
2. **求职最小闭环（D03–D06）**：简历解析确认 → 多源检索 → 排序分页 → 详情/研究入口 → 原页投递 → 状态记录。
3. **简历与研究（D07–D10）**：模板编辑导出、模型连接、Prompt 修改、JD/口碑研究与证据索引。
4. **自动化与收尾（D11–D12）**：定时检索、恢复行为、数据迁移、移除 MCP、桌面打包与本地验收。

首发平台先验证当前 macOS 环境；Windows/Linux 的能力在实际打包测试后再声明支持。
不引入多用户云平台、微服务、自动批量投递或复杂拖拽排版器。
先提供两款单栏简历模板，保证内容可读、分页正确，再扩充样式。

## 4. 不确定性处理

内嵌浏览器不等于完整 Chrome 产品，各平台登录、验证码、上传与新窗口行为必须早期实测。
若某平台无法可靠接入，将该来源标为暂不可用并记录原因；外部浏览器仅作为人工投递备选，不能据此宣称站内检索已完成。
公司官网按来源适配，不能将“招聘首页可打开”作为岗位抓取验收。
原型仅作为交互参考，其虚构岗位、分数及报告不能进入正式业务数据。

## 2026-09-19 用户确认的 UI 更新（D13）

侧栏保留发现岗位、岗位研究、已看过与资料设置；定时检索并入发现岗位，使用当前条件和权重冻结快照。城市使用可搜索多选、常用城市和不限，更多条件折叠。岗位研究接受发现上下文或安全岗位链接，无法取得正文时明确要求粘贴 JD；最终仅保留口碑调查、针对 JD 修改简历两个模块（D19 用户更正）。已看过只展示真实阅读事件，收藏和投递状态保留。侧栏宽度和折叠状态本地保存；原页是独立右侧面板，可拖动分隔、返回前进刷新关闭，窄屏切换工作区/原页。原生 bounds 跟随布局，拖动时隐藏原生 view 保证指针事件，不覆盖主内容或弹层。

## 追加 UI 决定（D14）

发现默认10条，列表独立滚动不带走右侧JD；统一方框居中小写j及程序图标。来源与账号改岗位来源，正常页面只展示名称、中文登录/检索状态及必要动作；技术证据留文档。11家登记官网均可在持久隔离面板人工浏览，浏览资格与检索资格分开。右上角提供浏览器开关，收起/关闭不清登录。模型预设覆盖DeepSeek、通义千问、智谱、豆包、Kimi、硅基流动、OpenAI、Claude、Gemini、Ollama、LM Studio及自定义；协议各自适配，不猜模型ID，免密钥仅显式本地回环服务。继续使用Electron内置Chromium，不增加第二浏览器。

### D14 补充交互决策（2026-09-19）

浏览器默认期望宽 760px，分栏最小 560px；不足以容纳正常工作区和网页时转主工作区模式。放大临时收起侧栏，返回恢复原宽度，不改变网页缩放或会话。侧栏使用统一语义 SVG 与名称 tooltip/aria-label，独立 panel-left 展开按钮固定顶部。来源会话采用既有稳定 userData 下的固定 persist 分区；不清理 Cookie/localStorage、不记录密码，明确提示临时会话/过期需重新登录。验收记录见 evidence/D14.md。

### D15 用户决定（2026-09-19）

优先显示界面，后台启动本地服务；Python 使用目录运行时减少重复解压。岗位来源页提供持久勾选，发现页与来源页同步多选偏好，勾选不绕过真实检索门禁。岗位研究仅需岗位链接，自动读取标题、公司及 JD 后确认研究；发现/已看过带入已有岗位，直接确认研究。读取受限时提供原页登录与重试，不要求手填其他字段、不编造缺失事实。

## 2026-09-19 后续确认：匹配四维与多标签

新规则仅技能、项目经历、学历、工作经验，默认35/30/15/20，合计100；城市、薪资、招聘类型仍是硬过滤。未知不能当满足；项目按真实项目证据计算。旧规则/任务快照保持历史含义，新规则以新版本存储。规则页展示实际评分预览，无岗位明确空态。

浏览器改为多标签，每标签独立URL和历史，同平台共享既有persist partition；只显示活动view。不同岗位新增，同URL复用，支持关闭相邻回退和上限，普通 HTTP/HTTPS 新窗口进入标签（D23 更新，继承打开者会话）。后台检索视图与前台隔离。


## D21–D23 用户追加决定（2026-09-19，覆盖早期同类约束）

- 发现/记录复用岗位操作组件：投递链接为主操作，收藏是可切换星标，已读/已投递在次级状态菜单更新。打开链接不等于投递。横向筛选弹出浮层，不推移结果；支持键盘退出、焦点返回和原生网页遮挡。
- 匹配以可编辑提示词为主，提供通用、校招/实习、社招模板；四项数值权重收进高级设置。保存生成不可变版本并设为当前规则，下次检索及新建任务使用它，既有任务冻结原版本。历史旧维度只读，不改含义。
- 本地模式不调用模型，自由提示词明确不生效。显式保存模型模式后，先显示本地结果，再对前1–20个候选执行一次有界重排（60秒、最多8000输出tokens）；其余候选顺序保留。模型提供双向逐字证据，未知可不给分；集合/分数/引用验证失败保留本地结果。派生新快照，不覆盖原始或历史结果。界面显示覆盖与取消，定时部分失败同样可见。
- 模型连接配置随规则冻结；主进程从安全存储取密钥，仅通过鉴权回环API发送，不存入规则/renderer。简历分析排除基本信息并过滤常见身份字段，JD作为不可信资料。匹配规则页不再保留实际岗位试算区；保留规则编辑、保存启用与四维设置。无确认简历展示“尚未评分”。实际付费模型效果另行验证。
- 前台浏览允许普通HTTP/HTTPS网页、ATS/SSO跳转及跨域新标签，不按招聘域名名单拒绝。登记平台入口仍用固定分区，新窗口继承打开者分区；未知入口用独立通用持久分区。前台放开不赋予自动采集或后台提取资格，来源能力/登录门禁仍有效。
- 保留sandbox、contextIsolation、webSecurity、证书检查，远程无Node/preload/应用IPC。特殊协议、账号内嵌URL与本地/内部地址受限；站点权限需明确选择，下载走保存对话框，不自动唤起外部应用。本产品使用Chromium网页行为，不承诺Chrome全部扩展或系统整合能力。


### D24 浏览器比例（2026-09-19）

标签行下使用单行导航、地址省略、缩放及放大/关闭；实际高度驱动原生bounds。适应宽度每次以100%重新测量文档及可见内容布局（兼容根部overflow隐藏），最多3次只缩小修正，上限100%、下限30%。加载未稳定或导航时提示稍后重试，不修改网站DOM；重复适应幂等，手动缩放/重置及每标签独立状态保留。真实腾讯页验证见[D24证据](evidence/D24.md)。

## 新标签浏览与搜索（2026-09-19 用户追加）

“搜索关键词或输入网址”搭配可选招聘网站和百度/Bing选择，按钮为“打开”。网址优先于网站选择；网站加关键词为所选引擎的站点限定搜索，页面提前明确目标；仅网站打开首页，均空时禁用。默认 Bing，选择持久化；提供清除网站恢复全网搜索。每次仅一个目标，独立于发现岗位的自动检索。

## D28 入口纠正（2026-09-19，取代 D27 混合新标签表单）

新标签明确区分打开招聘网站与网页搜索：前者首页/网址、无引擎；后者关键词、Bing/百度/Google、可选登记域名范围、短摘要与搜索按钮。引擎偏好本地持久化。顶部统一地址栏独立固定 Bing 搜索，网址直接导航；已有标签使用校验后的 navigateBrowserTab IPC 保留同一浏览上下文与历史，后台来源边界不变。编辑草稿不随 URL 轮询覆盖，失焦/Escape/切标签取消草稿，IME Enter 不误提交。Google 外部安全验证不绕过、不等同于结果可用。

## D29 最新精简决定（2026-09-19，覆盖 D27/D28 对应入口）

新标签的网站模式删除可选网址与提示，只选择网站后打开首页；手动网址统一走顶部地址栏。网页搜索删除范围与限定网站功能，只关键词、引擎和搜索，始终不自动添加 site:。网站模式的选择和旧范围值不参与搜索解析，关键词也不改变网站目的地；引擎偏好继续持久化。统一表单宽度与紧凑排版，保留灰白主题、顶部默认 Bing/网址导航、已有历史/会话/D25遮挡行为。


## 2026-09-19 BOSS专项与拖动修复补充

先处理分栏拖动后原生网页空白；原生网页随分栏更新 bounds，拖动结束、捕获丢失、失焦、卸载和窄屏转换不得遗留隐藏状态。保留 D29 已登录实例。BOSS 专项复用 Electron 固定平台分区和稳定数据目录：自动依据已加载页面识别登录及列表可读性；手动/定时共享单来源队列，先列表去重后有限详情，缓存和有界滚动、进度取消、部分结果及风险暂停。离线实现与一次真实小批量验收拆开记录；BOSS完成后再扩展其他平台。详见任务 D30/D31a/D31b；不复制真实浏览器档案、不导出 cookies、不绕过验证。

## 2026-09-19 用户最新决定（D31b / D33 / D34）

## D35 用户确认的简历交互

我的简历采用持续对话：左侧导入确认/历史/追问，右侧修改前后与逐段决定；模板预览按需打开，模板与 PDF/DOCX/MD 导出集中在预览中，明确所选已保存版本，关闭保留对话。会话绑定基础版本及岗位，历史本地持久；未采纳候选不是事实，缺资料追问，旧版本不得覆盖当前版本。岗位研究仍仅口碑调查和针对 JD 修改简历；工作强度标签简化，移除薪资方向的新入口与默认查询，保留历史证据。

## D36 报告与来源

研究报告自动持久保存岗位ID/规范URL及公司/标题/JD快照。发现、已看过与研究历史可直接读取；再次研究新增版本，保留证据与更正，部分/失败如实标明。岗位研究采用明显描边按钮。来源两页同步持久多选、空选不请求、不可用明示；只用于下次请求，不重筛当前结果或更改历史任务。更多仅保留阅读状态，交互检索固定缺失保留与薪资交集，旧任务沿用冻结快照。完整JD仅呈现一次，列表摘要不冒充全文；未读到仅一句提示和右侧原页入口，BOSS保留简洁读取按钮。

## D42–D45 新增用户决定（2026-09-23）

岗位调研主流程收敛为单个紧凑“口碑调查”面板，仅选“公司评价”和“岗位情况”，可单选或双选；不要求自由问题，不让用户选择信息来源。公司、岗位、JD 和链接自动带入，缺公司时给最小补充入口。公司评价分别寻找正向与负向公开反馈，不能硬凑或推断总体；岗位情况查工作内容、强度、假期和员工福利。报告按主题分组，逐条保留原链接、时间、主体与适用范围、未查明项，JD 与员工反馈分开。旧报告与兴趣问题继续可读。
