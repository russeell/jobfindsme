# UI34 双核心流程改进方案

日期：2026-09-23。范围：现有 Electron/React 桌面界面；保留本地数据、来源适配、历史与原生浏览器能力。

| 观察 | 设计决策 | 验收标准 |
| --- | --- | --- |
| 主导航中核心工作与辅助设置相近，用户需辨认“岗位研究”的用途。 | 主入口写为“找工作”“口碑调查”，已看过保留在工作区；简历、匹配、来源、模型归入“设置与资料”。 | 默认与窄窗首次进入都能直接找到两条主流程和历史入口。 |
| 找工作首屏控件多，简历状态、来源选择与来源检查的关系不够清楚。 | 搜索输入和主按钮居首；显示简短简历参与状态；主筛选保留城市、薪资、经验、来源，其他筛选归入“更多”；来源弹层给出检查入口。 | 只需关键词与有效来源即可检索；未选来源、未登录或部分失败时下一步明确。 |
| 列表有重复评分/覆盖率，详情与列表视觉边界重。 | 岗位、公司、城市、薪资优先；无评分时不显示重复“尚未评分”；辅助标记压缩；详情只留查看原页、口碑调查、收藏为直观动作。 | 有内容岗位在普通与约 860px 窗口可读；选中项明显，列表/详情独立滚动，窄窗切换可返回。 |
| 调查表单的复选框细小且边框密集；报告首屏有多次免责声明和重复空结果。 | 两张可多选主题卡与一个“开始调查”按钮；已有报告先显示对象、时间、主题、状态与证据；新调查折叠为次级操作。无证据只给一个诚实空态和下一步。 | 首次选择岗位后无需配置来源或必填文本即可开查；报告不会因无证据生成评价结论；旧报告问题仍可见。 |
| 原始状态枚举和逐源诊断抢占报告阅读空间。 | 面向用户的状态统一中文；来源诊断、限制与 JD 线索折叠；每条证据的原链接、发布时间紧邻摘录。 | 报告首屏不露内部枚举；证据可核对来源与时间，JD 清楚标为非口碑。 |
| 来源全目录结果长且卡片重复。 | 检查入口保留但摘要优先，20 条逐源结果默认折叠；选来源、批量检查、登录分别标记；窄窗可滚动。 | D44 本次/缓存/未探测语义不变，所有操作可达且不改变已有选择。 |
| 简历历史与导出占用维护首屏。 | 当前简历及维护/替换作为主区；历史和预览继续按需展开。 | 当前版和参与检索状态一眼可见；历史删除/恢复保护不变。 |
| 文本普遍偏小，多重边框、大空态和窄窗弹层挤压阅读。 | 统一至少 12px 正文、16px 行高/8px 间距节奏；白灰中性色；黑色仅强调主动作；聚焦可见，按钮有名称。 | 默认与约 860px 窗口无裁切/遮挡或空白原生页，键盘可达；根据截图修复具体问题后收尾。 |
| 原生浏览器可能占据窄窗工作区。 | 沿用按需打开及窄窗“工作区/浏览器”切换，保留已有尺寸与标签状态。 | 打开、返回、弹层和放大后仍可读且能恢复原位置，不强塞并列多栏。 |

实施次序：信息架构与调查结果 → 找工作与来源 → 简历和统一视觉 → 原生默认/窄窗复核与包审计。每个独立修复单独提交。验收只用合成岗位/报告与已有隔离资料；不运行全量招聘网站检索。

## 实施与验收结果

上述界面决策已在 D46 实施。主导航、搜索首屏、来源筛选、调查主题和报告证据层级均已调整；简历维护首屏显示当前版本及检索参与状态。原生隔离预览在 1162×768 和 854×768 窗口检查，见 [UI34 验收记录](UI34-evidence.md)。

隔离来源队列使用预览包的一源真实探测上限。首次验收发现队列完成后延迟通知会使逐源计数从 20 增至 24，现已阻止完成后追加通知；复测为已处理 20/20、逐源 20 条。普通包仅打包和审计，未启动。
