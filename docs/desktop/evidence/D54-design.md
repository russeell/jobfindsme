# D54 有界设计与验收

- 一个滚动容器承载研究正文；正文和 composer 共享工作区宽度。段落限制行长而不是收窄整个报告。顶部仅保留研究首页/找工作返回、历史及次级原页入口；composer 默认两行并自动增高到短窗允许值。
- 新的无岗位研究请求使用 `job_id=null`、明确 `context_company`、可选明确岗位名称及问题。SQLite 迁移把研究报告的 job_id 改为 nullable，保留岗位外键、旧报告和证据更正。绝不插入伪岗位。无岗位研究只选用户明确提及的公司；对象含糊则在原输入处澄清。研究沿用现有有界公开来源检索、原文核验及失败保留。
- 历史公司研究用公司与问题标识；岗位报告继续用真实岗位快照。旧报告保持原读法。前端不把无岗位报告塞进岗位上下文。
- 验收优先：迁移和无岗位 service/API 的离线检索桩，已有岗位报告兼容；输入的公司解析边界；原生合成报告默认/窄短窗与浏览器分栏。真实线上资料能否获得另列限制，不以合成数据冒充来源实测。
